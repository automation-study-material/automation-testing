    📱 Week 1: Mobile Testing Basics¶

    🎯 Goal: Understand Android fundamentals, APK files, installation process, permissions, storage, and how testers receive and install builds in real projects.

    📖 1. What is Android OS?¶

    Definition¶

    OS = Operating System

    Android OS is software that manages:

    • Mobile hardware
    • Applications
    • Memory
    • Storage
    • Network
    • Device resources

    Think of Android as the manager of your phone.

    When you:

    • Open WhatsApp
    • Take photos
    • Make calls
    • Use Google Pay

    Android OS manages all these activities.

    Examples¶

    Device Operating System
    Samsung Android
    OnePlus Android
    Vivo Android
    Oppo Android
    iPhone iOS

    Why Should a Tester Care?¶

    Different Android versions behave differently.

    Example:

    App works on Android 15
App crashes on Android 12

    This is called a:

    ✅ Compatibility Issue

    📖 2. Android Versions¶

    Android releases a new version almost every year.

    Version Release Year
    Android 12 2021
    Android 13 2022
    Android 14 2023
    Android 15 2024

    How to Check Android Version¶

    Settings
→ About Phone
→ Software Information
→ Android Version

    Why Test Different Versions?¶

    Example:

    Samsung S24 → Android 15
Samsung A52 → Android 13
OnePlus → Android 14

    Your application should work correctly on all supported versions.

    Interview Question¶

    Why is Compatibility Testing Important?¶

    Answer:

    Different Android devices and versions may behave differently, causing:

    • UI issues
    • Crashes
    • Functional failures

    📖 3. What is an APK File?¶

    APK stands for:

    Android Package Kit

    APK is the installation file for Android applications.

    Comparison¶

    Platform Installation File
    Windows .exe
    Android .apk

    Examples:

    whatsapp.apk
amazon.apk
banking.apk

    What Does APK Contain?¶

    An APK contains:

    • Application Code
    • Images
    • Icons
    • Configurations
    • Libraries
    • Resources

    Real Example¶

    Developer creates:

    MyApp_v1.0.apk

    Tester receives APK and starts testing.

    Interview Question¶

    What is APK?¶

    Answer:

    APK is an Android installation package used to install Android applications.

    📖 4. How APK is Generated¶

    Complete Flow¶

    GitHub Repository
       ↓
Clone Project
       ↓
Build Project
       ↓
APK Generated
       ↓
APK Stored On Laptop
       ↓
Install On Mobile
       ↓
Testing

    Clone Project¶

    Example:

    git clone https://github.com/company/mobile-app.git

    Build Project¶

    Android projects use Gradle.

    gradlew assembleDebug

    or

    ./gradlew assembleDebug

    Build Process¶

    Java/Kotlin Source Code
          ↓
Compilation
          ↓
Resource Processing
          ↓
APK Packaging
          ↓
APK Generated

    📖 5. Where is APK Stored?¶

    After build completes:

    project-root
└── app
    └── build
        └── outputs
            └── apk
                └── debug
                    └── app-debug.apk

    Example:

    C:\Projects\BankingApp\app\build\outputs\apk\debug\app-debug.apk

    📖 6. How Testers Transfer APK to Mobile¶

    After APK generation, testers need to install it on a real device.

    Method 1: WhatsApp¶

    Laptop
   ↓
WhatsApp Web
   ↓
Mobile
   ↓
Install APK

    Pros¶

    • Easy
    • Beginner friendly

    Cons¶

    • Not common in enterprise projects
    • File size limitations

    Method 2: Bluetooth¶

    Laptop
   ↓
Bluetooth
   ↓
Mobile

    Pros¶

    • No internet required

    Cons¶

    • Slow

    Method 3: Google Drive¶

    Upload APK
      ↓
Download On Mobile
      ↓
Install

    Pros¶

    • Easy sharing

    Cons¶

    • Requires internet

    Method 4: USB File Transfer¶

    Connect Phone
      ↓
Copy APK
      ↓
Install

    Pros¶

    • Fast
    • Reliable

    Cons¶

    • Manual process

    📖 7. How Real Testers Install APK¶

    Industry Standard: ADB¶

    Most companies use ADB.

    Enable Developer Options¶

    Settings
→ About Phone
→ Tap Build Number 7 Times

    Enable USB Debugging¶

    Settings
→ Developer Options
→ USB Debugging

    Connect Device¶

    Connect phone using USB cable.

    Allow:

    Allow USB Debugging?

    Select:

    Allow

    Verify Device¶

    adb devices

    Expected:

    List of devices attached

R58N123456 device

    Install APK¶

    adb install app-debug.apk

    or

    adb install C:\Projects\BankingApp\app\build\outputs\apk\debug\app-debug.apk

    How ADB Works¶

    Laptop
   ↓
Read APK
   ↓
USB Connection
   ↓
Transfer APK
   ↓
Android Package Manager
   ↓
Install App

    📖 11. App Permissions¶

    Applications need permissions to access device resources.

    Camera Permission¶

    Used for:

    • QR scanning
    • Taking photos

    Example:

    Google Pay QR Scanner

    Microphone Permission¶

    Used for:

    • Voice messages

    Example:

    WhatsApp Voice Messages

    Contacts Permission¶

    Used for:

    • Contact synchronization

    Example:

    WhatsApp Contacts

    Location Permission¶

    Used for:

    • Maps
    • Delivery Apps

    Example:

    Google Maps

    Storage Permission¶

    Used for:

    • Uploading files
    • Downloading files

    Permission Testing¶

    Scenario 1¶

    Allow permission.

    Expected:

    Feature works successfully

    Scenario 2¶

    Deny permission.

    Expected:

    Proper warning displayed
Application should not crash

    Common Defect¶

    Permission denied
Application crashes

    Severity:

    High

    📖 12. Internal vs External Storage¶

    Internal Storage¶

    Phone memory.

    Example:

    128 GB Device Storage

    Stores:

    • Apps
    • App Data
    • Settings

    External Storage¶

    Examples:

    • SD Card
    • Memory Card

    Why Testers Care¶

    When storage is full:

    Can app:

    • Save photos?
    • Download files?
    • Update itself?

    These are valid test scenarios.

    🔍 Mobile Logging & Debugging¶

    Why Are Logs Important?¶

    Suppose a user reports:

    Login is not working

    Without logs:

    Something is broken

    With logs:

    Network Issue
Backend Issue
Permission Issue
Application Crash
Database Issue

    Logs help identify the root cause.

    📖 What is Logcat?¶

    Android continuously generates logs while applications run.

    Example:

    User Clicked Login

Calling Login API

Response Received

Login Successful

    or

    Camera Permission Denied

Application Crashed

    All logs are stored in:

    Logcat

    Think of Logcat as:

    Application Logs
+
Crash Logs
+
Network Logs
+
System Logs

    🛠️ Viewing Logs¶

    Method 1: Android Studio¶

    Enable¶

    Developer Options
USB Debugging

    Open Logcat¶

    View
→ Tool Windows
→ Logcat

    Sample Logs¶

    LoginActivity Started

Calling Login API

Response 200 OK

Login Successful

    Method 2: ADB¶

    Verify Device¶

    adb devices

    Expected:

    List of devices attached

R58N123456 device

    Start Logcat¶

    adb logcat

    Filter Logs¶

    adb logcat | findstr MyApp

    🚨 Important Errors Every Tester Should Recognize¶

    Crash¶

    FATAL EXCEPTION

    Meaning:

    Application Crash

    Null Pointer¶

    NullPointerException

    Meaning:

    Developer Bug

    Network Timeout¶

    SocketTimeoutException

    Meaning:

    Server Not Responding

    Permission Issue¶

    SecurityException

    Meaning:

    Permission Missing

    📱 Scenario 1: Login Works on Android 15 But Fails on Android 12¶

    Question¶

    You tested the application on Android 15 and login works correctly.

    On Android 12 login fails.

    What will you do?

    Answer¶

    1. Reproduce issue.
    2. Open Logcat.
    3. Compare Android versions.
    4. Verify API responses.
    5. Verify permissions.
    6. Raise compatibility defect.

    Example¶

    Samsung S24 (Android 15)
Login Successful

Samsung A52 (Android 12)
Login Failed

    Log Investigation¶

    Possible Log:

    SocketTimeoutException

    or

    SecurityException

    🎤 Frequently Asked Interview Question¶

    Developer Gives You an APK. What Will You Test First?¶

    Answer¶

    1. Install APK
    2. Launch App
    3. Verify no crash
    4. Verify login
    5. Verify permissions
    6. Verify navigation
    7. Check logs if issues occur
    8. Begin functional testing

    🏆 Golden Rule of Mobile Testing¶

    ❌ Weak Defect

    App is not working

    ✅ Strong Defect

    Application crashes when camera permission is denied.

SecurityException observed in Logcat.

Crash reproduced on Android 14 and Android 15.

    This is the level of detail expected from strong mobile testers.
