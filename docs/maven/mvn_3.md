# 1. What is Maven Lifecycle Architecture?

Maven is designed around the concept of **Lifecycles**.

A **Lifecycle** is a collection of ordered **Phases**.

Each phase performs a specific task during the build process.

Together, these phases form a complete build process.

Think of Maven Lifecycle as a **roadmap** that tells Maven:

* What should happen first?
* What should happen next?
* What should happen last?

Instead of developers deciding the order manually, Maven follows a predefined architecture.

---

# Maven Architecture Overview

```text
                Maven

                  │

        ┌─────────┼─────────┐

        ▼         ▼         ▼

     Clean     Default     Site
    Lifecycle  Lifecycle  Lifecycle
```

Each lifecycle serves a different purpose.

---

# 2. Why Does Maven Have Multiple Lifecycles?

Imagine you're building a house.

Sometimes you want to:

* Clean the construction site.
* Build the house.
* Create documentation.

These are different activities.

Similarly, Maven separates responsibilities into three lifecycles.

| Lifecycle | Purpose                               |
| --------- | ------------------------------------- |
| Clean     | Remove old build files                |
| Default   | Build, Test, Package, Install, Deploy |
| Site      | Generate Project Documentation        |

This separation makes Maven modular and easy to use.

# 4. Clean Lifecycle

## Purpose

The Clean Lifecycle removes files generated by previous builds.

It ensures that every build starts from a clean state.

Without cleaning, old compiled classes or JAR files may remain and cause unexpected behavior.

---

## Main Phase

```text
clean
```

---

## Command

```bash
mvn clean
```

---

## What Happens Internally?

Suppose your project looks like this.

```text
MyProject

├── src
├── pom.xml
└── target
     ├── classes
     ├── test-classes
     ├── reports
     └── appium-framework.jar
```

When you execute:

```bash
mvn clean
```

Maven performs:

```text
Read pom.xml
      │
      ▼
Locate target/
      │
      ▼
Delete target/
      │
      ▼
Build Directory Clean
```

Result:

```text
MyProject

├── src
└── pom.xml
```

The **target** folder is removed.

---

## Why Do We Need Clean?

Suppose yesterday's build generated:

```text
DriverFactory.class
```

Today you rename it to:

```text
MobileDriverFactory.java
```

Without cleaning:

```text
target/classes

DriverFactory.class
MobileDriverFactory.class
```

Old files remain.

This can produce incorrect builds.

Running:

```bash
mvn clean
```

removes everything and forces Maven to rebuild from scratch.

---

# Real-World Example

Every Jenkins pipeline usually starts with:

```bash
mvn clean
```

This ensures the previous build does not affect the current one.

# 5. Default Lifecycle (Most Important)

This is the lifecycle used every day by developers.

It performs:

* Validation
* Compilation
* Testing
* Packaging
* Installation
* Deployment

---

## Default Lifecycle Phases

```text
validate
     │
     ▼
compile
     │
     ▼
test
     │
     ▼
package
     │
     ▼
verify
     │
     ▼
install
     │
     ▼
deploy
```

---

## Example

When you execute:

```bash
mvn package
```

Maven **does not** execute only the package phase.

Instead it executes:

```text
validate
      │
      ▼
compile
      │
      ▼
test
      │
      ▼
package
```

This is one of the most important Maven concepts.

---

## Why?

Because packaging requires:

* Valid project
* Compiled source code
* Successful test execution

Without these steps, creating a JAR would not make sense.

---

## Internal Architecture

```text
Developer

      │

      ▼

mvn package

      │

      ▼

Read pom.xml

      │

      ▼

validate

      │

      ▼

compile

      │

      ▼

test

      │

      ▼

package

      │

      ▼

target/app.jar
```

---

# Real-World Example

Suppose you build an Appium framework.

```text
DriverFactory

WaitUtils

ConfigReader

PageObjects
```

Running:

```bash
mvn install
```

Internally performs:

```text

↓

↓

test

↓

package

↓

verify

↓

install
```

Then copies the JAR to:

```text
C:\Users\<username>\.m2\repository
```

# 6. Site Lifecycle

The Site Lifecycle generates project documentation.

Unlike the Default Lifecycle, it does **not** build or package your application.

Instead, it creates reports.

---

## Command

```bash
mvn site
```

---

## Output

Examples of generated documentation:

* JavaDoc
* Test Reports
* Project Information
* Dependency Reports
* Plugin Reports

---

## Internal Flow

```text
Read pom.xml

      │

      ▼

Collect Project Information

      │

      ▼

Generate Reports

      │

      ▼

Generate HTML Site
```

---

## Output Folder

```text
target/site
```

Example:

```text
target

└── site
     ├── index.html
     ├── dependencies.html
     ├── plugins.html
     └── javadoc
```

---

## Is Site Lifecycle Used Frequently?

For automation projects,

**Not much.**

Most SDET projects rarely execute:

```bash
mvn site
```

It is more common in enterprise Java applications that require documentation.

# 7. Lifecycle vs Phase

Many beginners confuse these terms.

They are different.

---

## Lifecycle

A lifecycle is a **collection of phases**.

Example:

```text
Default Lifecycle

↓

validate

compile

test

package

verify

install

deploy
```

---

## Phase

A phase is a **single step** inside a lifecycle.

Example:

```text
compile
```

or

```text
package
```

---

Think of it like this.

```text
Book
 │
 ├── Chapter 1
 ├── Chapter 2
 ├── Chapter 3
```

Book = Lifecycle

Chapter = Phase

# 8. How Maven Chooses a Lifecycle

Suppose you execute:

```bash
mvn clean package
```

Does Maven run one lifecycle?

No.

It runs two.

---

Execution:

```text
Clean Lifecycle

↓

clean

----------------------

Default Lifecycle

↓

validate

↓

compile

↓

test

↓

package
```

First it removes old files.

Then it builds the project.

---

Another example:

```bash
mvn clean install
```

Execution:

```text
Clean

↓

clean

-------------------

Default

↓

validate

↓

compile

↓

test

↓

package

↓

verify

↓

install
```

# 11. Interview Questions

## Q1. How many lifecycles does Maven have?

**Answer:**

Maven has three built-in lifecycles:

* Clean
* Default
* Site

---

## Q2. Which lifecycle is used most frequently?

**Answer:**

The **Default Lifecycle**.

It handles validation, compilation, testing, packaging, installation, and deployment.

---

## Q3. Does `mvn package` execute only the package phase?

**Answer:**

No.

It executes all previous phases:

* validate
* compile
* test

before executing the package phase.

---

## Q4. Why do we execute `mvn clean`?

**Answer:**

To remove previously generated build files from the `target` directory and ensure that the next build starts from a clean state.

---

## Q5. Is Site Lifecycle mandatory?

**Answer:**

No.

It is optional and mainly used for generating project documentation and reports.

---

# 12. Summary

| Lifecycle | Purpose                                                    | Common Command                             |
| --------- | ---------------------------------------------------------- | ------------------------------------------ |
| Clean     | Removes previous build output (`target`)                   | `mvn clean`                                |
| Default   | Builds, tests, packages, installs, and deploys the project | `mvn package`, `mvn install`, `mvn deploy` |
| Site      | Generates project documentation and reports                | `mvn site`                                 |

---

# Key Takeaways

* Maven has **three built-in lifecycles**.
* A **Lifecycle** is a collection of **Phases**.
* The **Default Lifecycle** is the most important and is used in almost every Maven project.
* The **Clean Lifecycle** ensures a fresh build by deleting the `target` directory.
* The **Site Lifecycle** generates project documentation and reports.
* When you execute a Maven command such as `mvn package` or `mvn install`, Maven automatically runs all required phases in order, ensuring a consistent and reliable build process.
